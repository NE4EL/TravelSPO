# Неделя 3 — итоговый отчёт

**Проект** — TravelPlanner, веб-приложение для организации путешествий.

**Этап** — работа с планом поездки, проверка и упаковка приложения.

## Backend

- **Расписание.** Добавлены создание, перенос, редактирование и удаление мероприятия. Дата должна попадать в интервал поездки. Время окончания допускается, если задано начало. При сокращении поездки сервер проверяет уже запланированные мероприятия.
- **Расходы.** Каждая запись принадлежит одной поездке и может ссылаться на её мероприятие. Бюджет и суммы хранятся с двумя десятичными знаками. Карточка возвращает итог расходов и остаток. При удалении мероприятия расход сохраняется с пустой ссылкой.
- **Сбор вещей.** Пользователь добавляет и переименовывает вещи, ставит и снимает отметку о сборе, удаляет позиции. Состояние сохраняется в БД.
- **Проверки.** На временных базах SQLite прошли 10 автоматических тестов, включая отрицательный остаток, четыре недопустимые суммы, каскадное удаление, выход и изоляцию аккаунтов. [Тесты](../backend/tests/test_planner.py)

## Frontend

В карточке поездки появились вкладки «Расписание», «Бюджет» и «Вещи». Расписание сгруппировано по дням. На каждой вкладке видны лимит, расходы, остаток и количество собранных вещей. После сохранения клиент перечитывает карточку с сервера.

На собранном React-клиенте в DOM-окружении с реальным API проверена цепочка действий от регистрации до повторного входа. Созданы поездка, мероприятие и связанный расход. После отметки вещи счётчик изменился, после входа поездка осталась в списке.

## Инфраструктура

Vite собирает статические файлы, FastAPI отдаёт их с того же адреса, что и API. Compose описывает два сервиса — приложение и PostgreSQL 16. Сервер ждёт готовности БД и применяет миграцию при запуске. Данные хранятся в именованном томе.

Выполнены сборка клиента, проверка конфигурации Compose и генерация SQL миграции для PostgreSQL. Полный запуск контейнеров остаётся отдельной проверкой на машине с работающим Docker Engine. [Инструкция по запуску](../README.md#8-запуск)
